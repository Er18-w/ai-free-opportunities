# 每日更新说明（供维护 Agent 独立使用）

目标：更新现有网站，只公开真正够用的免费 AI 机会。普通小额、领取繁琐、排队低效的积分机会完全排除；即梦普通领积分属于用户明确排除范围，只有独立的大额活动、完整会员限免或显著效率改善才重新审核。

## 每日流程

1. 阅读 `AGENTS.md`、本文件、当前 `data/*.json` 和最近 `.runtime/reports/latest.json`；GitHub 运行时从 Actions 构件下载。
2. 运行 `npm run daily`。它核查 Groq 已公开记录并将 OpenRouter 零价模型写成内部候选；候选不会自动公开。
3. 查看失败来源。一次抓取失败只更新健康状态，不能宣布资源结束或删除公开记录。官方站返回 401/403 时标记为 `blocked` 并保留旧数据；只要其他来源仍正常，工作流继续完成并留下人工复核提示。
4. 审查 `.runtime/candidates/`。只有免费路径、资格、容量与效率均有官方证据的机会才能人工加入 `data/catalog.json`；未实测须写“规则已核，体验未测”。
5. 运行 `npm test`、`npm run validate`、`npm run build`。
6. 检查 `dist/` 不含候选数据，再提交本轮变更。已有持续发布授权时推送到主分支会触发 Pages 部署。

## 直接排除

- 不足以完成一项有意义任务，或没有修改/重试余量。
- 明显排队低效且没有独立特殊价值。
- 每日繁琐签到、看广告、拉人换少量体验。
- 完成目标、关键功能或导出需要付费。
- 折扣券、低价、BYOK客户端或本地模型冒充免费云端能力。

不同平台的 credits、tokens、neurons 不能直接比较。额度大但无法换算具体任务时保留为候选，不能公开。

## 推荐容量参考

- 文本 API：约 2000 字整理/改写加 2 轮修订，周期额度至少覆盖 3 项。
- 编程/通用 Agent：完成 1 项有验收结果的任务，并有 2 轮修改余量。
- 生图：同条件至少 6 次生成或编辑。
- 视频：同模型、时长、分辨率至少 3 次尝试，且可免费导出。
- 语音：约 30 分钟转写，或 1500 中文字合成并允许重做一次。
- 会员限免：关键功能开放，默认至少 7 天；更短活动要有明确特殊价值。

## 出错时

- `daily` 返回 10：所有来源都失败，先检查报告，last-good 保留。单个来源被阻止时会记录警告，但不会让每日流程永久失败。
- 测试、验证或构建失败：不要提交或发布，修复具体问题。
- GitHub 推送/Pages 失败：线上仍是旧版，不能说已经更新。
- 没有仓库写权限：交付候选 JSON、官方证据和变更说明，明确线上未变。

每日没有实质变化时无需制造资讯。新增、转收费、资格变化、活动结束或发布故障才需要提醒维护者。
